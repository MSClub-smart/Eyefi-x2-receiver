# Eye-Fi 카드 하드웨어 프로토콜 참고자료 (클라우드 없는 등록)

이 폴더의 `eyefi-config.c/.h`(+`eyefi-config-reference.tar.gz`)는 Dave Hansen 의 오픈소스
**eyefi-config** (GPLv2) 로, Eye-Fi X2 카드의 펌웨어 설정 프로토콜을 역분석해 구현한 것.
어느 클리닉 카드(00-18-56-12-34-57)의 EYEFI 폴더 안에 들어 있어 발견·보존함(2026-09-02).

## 핵심: 클라우드 없이 카드 등록이 가능한 이유
- **업로드키(인증 공유비밀)는 공장에서 카드에 이미 심어져 있다** (토큰 253 / `UPLOAD_KEY=0xfd`).
  클라우드는 이 키를 "만든" 게 아니라 사용자 계정에 매핑만 했다. 우리는 카드에서 직접 읽는다.
- 따라서 등록 = ①카드에서 MAC+업로드키 읽기 → receiver(cards.json)에 넣기
  ②카드에 클리닉 Wi-Fi(SSID+비번) 써넣기. 둘 다 리더에서, 클라우드 없이 됨. **실증 완료.**

## 메일박스 프로토콜 (DLL 없이도 가능한 원리)
카드 마운트의 `EYEFI/` 폴더에 4개의 16KB 고정크기 파일:
- `REQM` — 호스트→카드 명령 (Request Mailbox)
- `RSPM` — 카드→호스트 응답 (Response Mailbox)
- `REQC` / `RSPC` — 시퀀스번호 핸드셰이크용

핸드셰이크 (eyefi-config.c `wait_for_response`):
1. `init_card`: RSPM 0으로 지움, RSPC 에서 seq 읽어 +1 (없으면 0x1234)
2. 명령 구조체를 REQM 에 씀 (`'o'`=읽기 / `'O'`=쓰기 / `'a'`,`'d'`=망추가/삭제 / `'g'`스캔 / `'l'`목록 / `'b'`리부트)
3. seq 증가시켜 REQC 에 씀 → RSPC 가 그 seq 를 돌려줄 때까지 폴링(최대 15초) = 카드 펌웨어가 처리 완료
4. RSPM 에서 결과 읽기

## 서브커맨드 맵 (card_info_subcommand)
`1`=MAC, `2`=펌웨어, `3`=카드키(device secret), `4`=API URL(api.eye.fi),
`0xfd(253)`=업로드키, `17`=전송모드, `0x22~0x25`=다이렉트모드, `10`=WLAN on/off, `27`=endless.

## 우리 구현 대응
- 현재는 공식 `EyeFiCard.dll`(32bit) 경유로 같은 동작을 함: `card_wifi.py`(조회/테스트/추가/삭제),
  `card_reader.py`(MAC/업로드키 읽기). 리더에서 쓰기 커밋됨을 실증(테스트망 추가→목록확인→삭제).
- DLL 없이 순수 파이썬으로 위 메일박스 프로토콜을 직접 구현하는 것도 가능(이 소스가 청사진).
  DLL 이 없거나 크로스플랫폼이 필요할 때의 대안.

## 미해결
- **새 업로드키 쓰기**: 이 오픈소스도 업로드키는 읽기(`o 0xfd`)만 하고 쓰기 경로는 없음.
  키를 우리 맘대로 바꿔 심는 건 미검증(카드 기존 키를 쓰면 되므로 실무상 불필요).
- DLL `SetToken` 으로 토큰34(표시이름) 쓰기는 리더에서 커밋 안 됨(무관한 캐시로 추정).
  반면 `AddNetworkSettings`(Wi-Fi)는 정상 커밋 — 실무에 필요한 쓰기는 검증됨.
